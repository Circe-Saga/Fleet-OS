# Saga-Fleet — the Agent OS substrate + worker runtime

Workspace-scoped coordination for the Saga agent fleet. Design:
[`docs/DESIGN.md`](docs/DESIGN.md) · implementation briefs:
[`docs/briefs/`](docs/briefs/) · Conductor procedure:
[`conductor/PLAYBOOK.md`](conductor/PLAYBOOK.md) · adopting this for your own
fleet: [`ADOPTING.md`](ADOPTING.md).

**Thesis:** the v1 EvalLab fleet proved the state layer (addressed messages,
focused-but-complete briefs, checkpoints). What was missing is the **driver** — nothing wakes
an idle agent. v2 adds: a task graph with evidence-verified gates, headless resumable workers
in isolated worktrees, a session/cost ledger, protocol-enforcing hooks, and a self-draining
founder queue.

## Layout

```
fleet.py                  # the whole CLI (stdlib-only, SQLite WAL, single file like v1)
fleet.db                  # THE record (gitignored) — override with FLEET_DB
runs/                     # captured worker result JSON (gitignored)
hooks/                    # SessionStart brief-inject · Stop checkpoint-guard · PreCompact reminder
templates/worker-settings.json   # hook wiring stamped into each worker worktree by `spawn`
profiles/<model>.md       # model gotchas, curated from DISCOVERIES → injected into starters
conductor/PLAYBOOK.md     # the Conductor's tick procedure
tests/                    # unittest suite (fake launcher; scratch git repos; tmp DB)
```

## Quickstart (founder / Conductor)

```bash
cd Saga-Fleet
python3 fleet.py task add --objective "…" --kind implement --repo Saga-FastAPI \
    --done "<falsifiable criteria>" --budget 10 --context "path/to/spec.md :: the contract"
python3 fleet.py task set-state --id 1 --state IN_PROGRESS --actor conductor
python3 fleet.py spawn --task 1 --model sonnet --dry-run    # inspect, then drop --dry-run
python3 fleet.py tick                                       # harvest · expire · reconcile · queue
python3 fleet.py status | python3 fleet.py digest --json
cat ../WAITING_ON_YOU.md                                    # your queue (regenerated by tick)
```

Workers get their brief injected at session start (hook) and cannot end a turn without a
checkpoint (hook). They claim evidence (`fleet task evidence`); only the Conductor grants
IN_REVIEW/DONE, after `fleet verify` re-runs the claim. Decisions raised with
`--reversible --default … --expires H` auto-proceed — the queue drains itself.

## Role-class agents (any team, not just SWE lanes)

Any agent can carry a standing **role prompt** — `--role-prompt "path[#heading],…"` on `set`
or `spawn` (paths relative to the workspace; `#heading` extracts one section of a shared doc,
so one cabinet file serves nine roles unsplit). The role text rides the worker's system prompt
on every spawn AND resume, so identity survives compaction; the task brief stays the user
prompt. Leadership conventions (doc-task gates, weekly memo cadence, self-filed tasks):
`conductor/PLAYBOOK.md` §"Role-class agents". The Saga leadership cabinet is pre-seeded —
`python3 fleet.py status` lists the `leadership`-layer agents; address them all at once with
`fleet msg --to leadership`.

## Agent runtime vs product inference (where Bedrock does and doesn't appear)

The fleet runs agents **exclusively through Claude Code** (`claude -p --resume`, headless) or
the Codex CLI — your existing CLI auth, session resume, hooks, and permission modes for free.
**No direct model API calls, no boto3, no Bedrock credentials anywhere in this repo or its
tests** (grep-verifiable). The Bedrock mentions in `profiles/*.md` are knowledge FOR agents
who write code against Saga's *product* pipeline, which calls Bedrock in prod/EvalLab — that's
product inference, a separate layer with its own (F10) platform strategy, not how agents run.

## Models

Agents store a model **alias** (`haiku`/`sonnet`/`opus`/`fable`); the `MODELS` registry in
fleet.py resolves real ids at launch, so a new model = one registry line + a
`profiles/<alias>.md`. Track with `fleet models` (registry, per-agent assignment, spend by
model, recent switches) and `fleet report` (spend by model per window). Switch with
`fleet set --slug X --model opus` or mid-conversation via `fleet run --agent X --model opus
--input …` (persists on the agent row, logged as a `model-switch` event). Every run row
records the model that powered it. Escalation policy: `conductor/PLAYBOOK.md` §"Model strategy".

## Kestral (leadership mirror)

One-way, best-effort, Conductor-driven: `fleet kestral-pending` dumps everything needing a
push (with the probed mapping hints — 3-status limit, tags for blocked/needs-user, decisions
assigned to the founder); the Conductor drives the Kestral MCP and stores returned ids via
`fleet kestral-mark` so pushes stay idempotent. fleet.db is the record; Kestral is a view;
workers never touch it and its downtime never blocks anything (PLAYBOOK §5b).

## Tests

```bash
python3 -m unittest discover -s tests -v   # 36 unit/integration tests (fake launcher, tmp DBs)
python3 tests/e2e.py                       # full golden-path e2e, simulated worker (free, CI-safe)
python3 tests/e2e.py --live                # same path with a REAL headless claude worker (~$0.20)
```

The e2e drives the whole loop in a throwaway sandbox: task → spawn (worktree + hooks) →
worker edits code, claims evidence, checkpoints → harvest (cost/session) → verify gate →
review policy → review blocks DONE → clears → decision auto-proceed → tick → founder queue →
retire → events audit. 25 checks; exit 0 = pass.

## Migration from the EvalLab fleet (v1)

The schema upgrades a v1 `fleet.db` in place on first connect (idempotent column adds).
To adopt: copy EvalLab's DB here (SQLite `.backup`, never raw `cp` of a live WAL db), or point
`FLEET_DB` at it. EvalLab's `evals/scripts/fleet.py` keeps working against its own DB until
cutover; both understand the same core tables.
